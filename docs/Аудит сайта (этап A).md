# UX/UI-аудит сайта tbgroup.kz (этап A)

Методика: скриншоты живого прода (8 страниц, 12.07.2026), построчный разбор кода `client/src`,
сверка с бренд-буком (`BrandBook/brand book TB Group.pdf`). Скриншоты в сессионном scratchpad;
при необходимости пересъёмка: headless Chrome, `--virtual-time-budget=25000`.

## Сводный вердикт

Сайт построен на чужой визуальной системе: сине-голубой «AI corporate» шаблон
(navy `#0B1F3A` + голубой `#2D9CDB`). **Ни один из пяти фирменных цветов, ни фирменный
градиент, ни Michroma, ни настоящий логотип, ни один графический мотив бренд-бука не
используются нигде.** Дополнительно найдены: горизонтальный overflow на мобильной главной,
страницы-«призраки» с почти нулевым контентом и три разных самодельных «логотипа».

| Категория | Оценка | Ключевая проблема |
|---|---|---|
| Цвет | 🔴 0/10 | Палитра целиком чужая; бренд-цветов нет |
| Типографика | 🔴 1/10 | Только Inter с CDN; нет display-уровня; иерархия только размером |
| Логотип/айдентика | 🔴 0/10 | Текстовые бейджи «TB» в 3 разных вариантах; фирменного знака нет |
| Графика/паттерны | 🔴 0/10 | Blur-блобы вместо фирменных орбит/точек/волн |
| Иконки | 🔴 0/10 | 14 эмодзи (📦👥📞⚙️…) — платформозависимы, вне стиля |
| Компоненты | 🟠 2/10 | Функциональны, но «типовой Tailwind»: glass, rounded-2xl, грид ×3 |
| Анимации | 🟠 3/10 | Единый fade-up для всего; фирменного движения нет |
| UX-структура | 🟡 5/10 | Логика страниц здравая; ритм монотонный, есть пустые страницы |
| Адаптив | 🟠 3/10 | Mobile: горизонтальный overflow на главной (баг) |
| Тон/контент | 🟡 4/10 | Слоганы бренда не используются; гео-акцента (Казахстан) нет |

## 1. Сквозные системные проблемы

### 1.1 Цвет
- Вся палитра — [tailwind.config.js:8-15](../client/tailwind.config.js#L8-L15):
  `navy #0B1F3A`, `accent #2D9CDB` (голубой), `gray #F4F6F9`. В бренд-буке этих цветов нет.
- Фирменный градиент purple→magenta→orange отсутствует. Единственные градиенты на сайте —
  голубой blur в Hero и placeholder «Фото офиса» — оба вне бренда.
- Курьёз: единственное «попадание» в бренд — звёзды рейтинга `text-yellow-400`
  (= `#FACC15` = TB Group Yellow), и то случайное.
- Роли (Primary/Surface/Border/Hover/Disabled) как система не описаны — цвета захардкожены
  по компонентам.

### 1.2 Типографика
- Один шрифт Inter, грузится с Google CDN ([index.html:10](../client/index.html#L10)) —
  противоречит и бренду, и политике self-host (безопасность: на сервере уже закручены
  nginx-заголовки, а шрифты ходят на сторонний CDN).
- Display-уровня нет: `.heading-1/-2` — это просто Inter Bold разных размеров
  ([index.css:37-42](../client/src/index.css#L37-L42)). Michroma не подключена.
- Шкала неполная: нет Caption/Label/Overline; «подпись секции» — это uppercase Inter
  голубого цвета ([Section.jsx:18-20](../client/src/components/home/Section.jsx#L18-L20)).

### 1.3 Логотип и айдентика
Фирменного знака (пиксельный «роспад» + T/B) нет нигде. Вместо него три разных самоделки:
- Navbar: квадрат navy + голубые буквы «TB» ([Navbar.jsx:24-27](../client/src/components/layout/Navbar.jsx#L24-L27))
- Footer: квадрат голубой + белые буквы ([Footer.jsx:13-15](../client/src/components/layout/Footer.jsx#L13-L15))
- Favicon: navy + голубой текст ([favicon.svg](../client/public/favicon.svg))

Три версии не совпадают даже между собой — прямое нарушение раздела 1.6 бренд-бука
(«используйте только утверждённые версии»).

### 1.4 Графика и паттерны
Ни один мотив бренд-бука не использован: нет орбит/частиц, волновых линий из точек,
точечного паттерна, круговых process-колец, изометрических иллюстраций, диагонали 2pt.
Вместо них — размытые голубые круги (`blur-3xl`) в Hero
([Hero.jsx:61-68](../client/src/components/home/Hero.jsx#L61-L68)) — «типовой AI-блоб»
из запрещённого списка брифа.

### 1.5 Иконки
14 эмодзи: 📦👥📞☁️ в ServicesGrid + ⚙️✅🌐🏢💬📄📊📱🔗🤝 в
[serviceContent.js](../client/src/data/serviceContent.js). Эмодзи рендерятся по-разному
на Windows/macOS/Android, не масштабируются, не перекрашиваются и не имеют отношения
к линейной градиентной иконографике бренд-бука (стр. 20).

### 1.6 Компоненты: совпадения с «запрещённым списком» брифа

| Запрет из брифа | Где встречается сейчас |
|---|---|
| Стеклянные карточки (glass) | `.glass` — 20+ мест: карточки услуг, кейсов, отзывов, статистика Hero, формы, FAQ, навбар |
| Круглые блобы | Hero: два `rounded-full blur-3xl` |
| Типовые Hero | Центрированный бейдж → заголовок → 2 кнопки → грид статистики |
| Типовые кнопки | `.btn-primary` — плоская голубая пилюля |
| Типовые AI-карточки | `rounded-2xl p-6 + hover:-translate-y-1` везде |
| Случайные иконки | Эмодзи (хуже Heroicons) |
| Типовые AI-секции | «Центрированный заголовок + грид ×3/×4» — все 6 секций главной |

### 1.7 Анимации
Одна и та же анимация для всего: `fade + y:15-30, stagger 0.05-0.1`
(framer-motion `whileInView`). Нет: фирменного reveal, движения градиента, параллакса,
анимации цифр, hover-эффектов сложнее `translate-y`. Прелоадер — голубой спиннер
на весь экран (типовой).
⚠️ Риск: карточки с `initial={{opacity:0}}` + `whileInView` при сбое JS/observer остаются
невидимыми — на прод-скриншотах секции «Преимущества»/«Возможности» пустые (в headless);
проверить поведение на слабых устройствах и для SEO-ботов.

## 2. Постраничный разбор

### 2.1 Главная `/`
- **Hero:** бейдж-пилюля, заголовок с голубыми вставками, 2 кнопки, 4 glass-карточки
  статистики. Композиция статичная, слоёв/глубины/фирменной графики нет. Слоганы бренда
  не используются.
- ~~🐞 Mobile (390px): горизонтальный overflow~~ **ОПРОВЕРГНУТО на этапе C
  (2026-07-12):** «обрезка» оказалась артефактом среды съёмки — headless Chrome на
  Windows клампит минимальную ширину окна (~489 CSS px), и кадр 390px просто резал
  вьюпорт. Честная проверка через CDP `Emulation.setDeviceMetricsOverride` (390px)
  показала `scrollWidth = 390` — переполнения нет ни в старой, ни в новой вёрстке.
  Для будущих мобильных скриншотов использовать CDP-эмуляцию (`cdp_shots.py`),
  а не `--window-size`.
- Секции идут монотонным ритмом: 6 × «центрированный заголовок + грид карточек».
  Визуальной кульминации нет; CTA-блок и форма дублируют контакты.
- Тёмная тема: navy-карточки на navy-фоне — секции сливаются.

### 2.2 Услуги `/services/*` (МойСклад, Битрикс24, Телефония)
- Шапка: navy-блок с заголовком — единственная «фирменная» попытка, но цвет чужой.
- Преимущества — плоские белые плашки со звёздочкой ★ в голубом круге; выглядит как
  списки задач, не как продающий блок.
- «Возможности платформы» — glass-карточки с эмодзи и чек-листами ✓.
- На проде: секции визуально пустые до скролла (см. 1.7), между шапкой и формой — огромные
  простои по вертикали.
- Форма + контакты: рабочая связка, но email — `@gmail.com` (бьёт по доверию B2B;
  вопрос за пределами дизайна — отметить заказчику).

### 2.3 Кейсы `/cases`
- Контента: **1 кейс** (Timing.kz). При этом сверху полноразмерный поиск + фильтр по
  услугам — интерфейс для сотен записей поверх одной. Страница на 90% пустая.
- Карточка кейса: glass, без изображения, без метрик на превью.

### 2.4 Кейс `/cases/:slug`
- Структура здравая (метрики → задача → решение → результат), но метрики
  `grid-cols-3` не адаптируются на мобиле (сожмутся), галерея и видео — опционально.

### 2.5 Отзывы `/reviews`
- На проде отзывов **ноль** → страница состоит из одной формы «Оставить отзыв»
  по центру пустого экрана. Страница-призрак, вредит доверию.
- По коду: карусель со стрелками-кнопками `← →` (текстовые символы в btn-outline) +
  жёлтые звёзды-символы `★` — вне любого стиля.

### 2.6 О компании `/about`
- «Команда» на проде пустая (секция с заголовком без контента); в дефолтах — 4 человека
  с кружками-инициалами. ⚠️ Дефолтные имена выглядят как плейсхолдеры — проверить
  с заказчиком реальность данных.
- «Сертификаты и партнёры» — 5 текстовых пилюль, хотя это сильный B2B-аргумент
  (заслуживает логотипов).
- «Офис» — placeholder «Фото офиса» на градиенте — прямо на проде.

### 2.7 Контакты `/contacts`
- Карта — пустой синий прямоугольник (координаты не заданы в админке; iframe не рендерится).
- Список контактов + форма — ок функционально, вне бренда визуально.

### 2.8 404
- Голубые «404» + кнопка. Нейтрально; шанс на фирменный момент (например, пиксельный
  роспад знака) упущен.

## 3. UX-выводы и входные данные для этапа B

1. **Структура страниц сохраняется** (бриф: бизнес-логику не менять) — меняется визуальная
   система. Кандидаты на композиционные правки (разрешены брифом):
   - `/reviews` и `/cases`: спроектировать «красивое пустое состояние» и режим малого
     контента (1–3 записи) — сейчас дизайн рассчитан на изобилие, которого нет;
   - фильтры на `/cases` показывать от N ≥ 6 записей;
   - CTA-блок главной и «Контакты»: убрать дублирование формы или дифференцировать.
2. **Контентные ограничения** (учесть в дизайне): 1 кейс, 0 отзывов, нет фото команды
   и офиса, нет логотипов партнёров. Дизайн-система должна выглядеть достойно при
   минимуме контента и масштабироваться при росте.
3. **Тех-долг, влияющий на редизайн:**
   - mobile overflow на главной (баг — чинить в любом случае);
   - Inter c Google CDN → перевести на self-host вместе с новыми шрифтами;
   - `App.css` — мёртвый код от Vite-шаблона (`.counter`, `.hero .vite`) — не используется;
   - фолбэк-риск `whileInView` (пустые секции без JS/observer);
   - прелоадер заменить на фирменный.
4. **Тёмная тема** — сейчас дефолт для пользователей с тёмной ОС (prefers-color-scheme),
   и именно она самая слабая визуально. Аргумент за проработку Dark-first концепции
   наравне со Light-first (решение — на этапе B, после сравнения).
5. **Тон:** ни один слоган бренд-бука не используется; гео-привязка «Казахстан»
   отсутствует в текстах (при том что домен .kz и адрес — Алматы).

## 4. Что делает этап B (по итогам аудита)

Полная дизайн-система: Design Tokens (цвет-роли, типошкала, spacing 8pt, радиусы, тени,
бордеры, сетка, состояния), конкурс display-шрифта кириллицы (3+ кандидата), две концепции
Light-first / Dark-first, UI-kit на замену всем перечисленным компонентам, фирменные фоны
(3 варианта), Hero как уникальный актив бренда, спецификация анимаций.
Формат: HTML-стайлгайд + markdown-концепция. См. `Ребрендинг TB Group.md`.
